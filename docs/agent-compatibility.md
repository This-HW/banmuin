# docs/agent-compatibility.md — 에이전트 호환성 가이드

> 이 시스템의 본체는 코드가 아니라 AI 에이전트가 읽고 실행하는 문서
> (`skills/`, `playbooks/`, `bin/`, `templates/`)입니다.
> 아래 최소 요구사항을 만족하는 에이전트라면, 제품 종류와 무관하게 동작하도록 설계되어 있습니다.

## 1. 에이전트 최소 요구사항 체크리스트

새 에이전트에 이 시스템을 올리기 전, 전부 "예"여야 합니다.

| # | 요구사항 | 왜 필요한지 |
|---|---|---|
| 1 | 파일 읽기/쓰기 (Markdown, YAML, JSON, 셸 스크립트) | 스킬·지식파일·상태를 파일로 주고받음 |
| 2 | 셸 명령 실행 (POSIX sh 호환) | `bin/*.sh` 실행 (락·킬스위치·로그) |
| 3 | HTTP/API 호출 | Meta·Threads·Instagram·YouTube·Higgsfield API, 웹 검색 |
| 4 | 로그인 세션이 유지되는 브라우저 자동화 | 네이버 블로그 발행·삭제·카드뉴스 렌더링 (`playbooks/`) |
| 5 | 스케줄 실행 (cron 또는 동등 기능) | 매일 06:30 루틴, 주간 캘린더 등 정기 기동 |
| 6 | 장시간(수십 분~수 시간) 작업 수행 | 수집→분석→제작→검수→발행→보고 전체 루틴 |
| 7 | 시크릿을 안전하게 보관·주입하는 방법 | API 키·토큰을 평문 파일에 남기지 않기 위해 |

**판정**: 하나라도 "아니오"면 해당 에이전트에서는 동작하지 않습니다.
특히 #1·#2가 안 되는 **순수 채팅형 에이전트**(대화만 되고 파일·셸 접근이 불가한 경우)는
이 시스템을 실행할 수 없습니다.

## 2. 사용하는 오픈 표준

특정 AI 제품에 종속되지 않기 위해 아래 공개 표준만 사용합니다.

| 표준 | 용도 | 비고 |
|---|---|---|
| `AGENTS.md` | 저장소 루트의 에이전트용 작업 지침 | 여러 코딩 에이전트가 채택한 관례 |
| `SKILL.md` (Anthropic Agent Skills) | `skills/*/`의 역할 정의 형식 | 오픈 스펙. `SKILL.md` + 참조 파일 구조 |
| MCP (Model Context Protocol) | 외부 서비스 연동 (API 호출) | 오픈 프로토콜 |
| Markdown + YAML + 셸 | 모든 지시서·설정·실행 래퍼 | 특정 제품 문법 사용 금지 |

기여 시 특정 제품 전용 문법·경로·도구를 하드코딩하지 마세요
(상세: `CONTRIBUTING.md` 5장).

## 4. 어댑터 가이드 — 새 에이전트에 적용할 때 바꾸는 것

코어(`skills/`, `playbooks/`, `bin/`, `templates/`, `SPEC.md`)는 그대로 두고,
아래 4곳만 에이전트/환경에 맞게 맞춥니다.

### 4.1 시크릿 관리
- `businesses/<slug>/secrets.env`는 Git에 절대 커밋하지 않습니다.
- 각 에이전트의 시크릿 관리 방식에 맞게 주입합니다
  (예: Muse의 Secure Vault, 환경 변수, 에이전트별 secret store).
- 규칙: 시크릿 값을 로그·리포트·프롬프트 출력에 남기지 않습니다.

### 4.2 스케줄러 등록
- 기준: cron (`TZ=Asia/Seoul`), `templates/config.yaml`의 `schedule` 섹션 참조.
- cron을 쓸 수 없는 환경이면 동등 기능(에이전트 내장 스케줄러, 시스템 타이머 등)으로
  같은 시각에 `bin/run.sh --business <slug>`를 기동합니다.

### 4.3 스킬 설치 경로
- `skills/*/`는 저장소 안에 있지만, 에이전트에 따라 전역 스킬 경로에 설치해야 할 수 있습니다
  (예: Muse는 `~/.claude/skills/`).
- 설치하지 않고 저장소 경로를 직접 읽게 해도 됩니다. 중요한 것은
  **오케스트레이터가 `SKILL.md`들을 읽을 수 있는 경로**에 두는 것입니다.

### 4.4 브라우저 도구 교체
- 기본값: `playbooks/*.task.md`는 Aside(브라우저 자동화 도구)를 전제로 작성되어 있습니다.
- Aside를 쓸 수 없는 환경이면, **플레이북 형식을 유지한 채** 실행 도구만 교체합니다:
  플레이북(사전조건·단계·성공 기준·실패 보고)은 그대로 두고,
  "이 지시서를 실행하는 주체"를 해당 환경의 브라우저 도구로 바꿉니다.
- Playwright 코드 방식으로는 돌아가지 않습니다 (SPEC v1.2에서 제외됨).

## 5. 비호환 예시

- 순수 채팅형 에이전트 (파일 읽기/쓰기·셸 실행 불가) → 체크리스트 #1·#2 불충족으로 불가
- 브라우저 자동화가 전혀 없는 환경 → 네이버 발행 플레이북 실행 불가
  (API 채널만 쓰는 축소 운영은 가능 — `config.yaml`에서 `naver_blog.enabled: false`)
- 스케줄 기능이 없는 환경 → 수동으로 `bin/run.sh`를 실행하는 반수동 운영은 가능
