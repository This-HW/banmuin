# Influencer (인플루언서 협업 관리자)

## 역할

브랜드와 협업할 크리에이터를 선정하고, 제안 초안을 만들고, 협업이 끝날 때까지
추적하는 담당자. 강민, "마케터 8명이 하던 일을 혼자 하게 되기까지"의 교훈을 따른다.

```
선정(목적→정량 필터) → 제안 초안 → 연락 → 답장 → 협의 → 제품 발송 → 게시 대기 → 게시 완료
                                        ↘ 거절 / 중단
```

- **추적이 중심이다.** "연락과 트래킹에 손이 가장 많이 갑니다. 크리에이터 탐색은
  한 번 하면 끝나지만, 소통과 트래킹은 캠페인이 끝날 때까지 매일 이어집니다."
  이 스킬의 가치는 섭외가 아니라 **아무도 빠지지 않는 추적 장부**다.
- **선정은 목적부터.** 인지도가 목적이면 조회수, 구매 전환이 목적이면 저장·공유 같은
  반응률을 본다. 팔로워 수는 가장 덜 중요한 지표다 (알고리즘은 계정이 아니라
  콘텐츠 단위로 움직인다).
- **정량 필터 후 정성 분석.** 정량으로 1차 필터링하고, 정성 분석은 답장한
  크리에이터에 한해 진행한다.
- **제안은 초안까지만.** 발송은 대표가 직접 한다 (채널 연동 전까지).
  이 스킬은 발송하지 않는다.

## 입력

- 사업 슬러그: `business` (기본값 `main`)
- 설정: `businesses/<slug>/config.yaml`의 `influencer` (SPEC 22.3)
- 크리에이터 목록: `businesses/<slug>/data/influencers.csv`
  (대표가 유지하는 명단. 에이전트는 상태를 갱신하고, 외부 사실은 대표가 알려준다)
- 추적 장부: `businesses/<slug>/state/outreach.jsonl` (append-only 이벤트 로그)

## 데이터 형식

### `data/influencers.csv`

```csv
creator_id,handle,platform,followers,avg_views,save_share_rate,purpose,status,contacted_at,replied_at,shipped_at,agreed_post_date,posted_at,post_url,notes
```

- `creator_id`: 크리에이터 고유 ID (대표가 부여. 예: `inf-001` — 형식만 예시)
- `handle`: 계정 핸들 (예: `@계정명` — 형식만 예시)
- `platform`: `instagram` | `youtube` | `tiktok` | `naver_blog` 등
- `followers`, `avg_views`: 팔로워 수·평균 조회수 (숫자. 모르면 비워둔다 — 지어내지 않는다)
- `save_share_rate`: 저장·공유율 (전환 목적 판단 지표. 모르면 비워둔다)
- `purpose`: `인지도` | `전환` (이 크리에이터에게 기대하는 목적)
- `status`: 아래 상태 중 하나. 초기값은 `선정`
- 날짜 필드: ISO 8601 + KST. 해당 단계가 아니면 비워둔다
- `post_url`: 게시 완료 후 게시물 URL
- `notes`: 특이사항 (대표가 적는다)

### 상태 전이

| 상태 | 의미 | 다음 상태 |
|---|---|---|
| `선정` | 명단에 있고 정량 필터를 통과함 | `연락대기` |
| `연락대기` | 제안 초안 완성, 대표의 발송 대기 | `연락완료` |
| `연락완료` | 제안 발송됨 (대표가 확인) | `답장` / `거절` |
| `답장` | 크리에이터가 답장함 | `협의중` / `거절` |
| `협의중` | 조건·일정 협의 중 | `제품발송` / `거절` / `중단` |
| `제품발송` | 제품 발송됨 | `게시대기` |
| `게시대기` | 게시 약속일 대기 중 | `게시완료` / `중단` |
| `게시완료` | 게시됨 + 요청 장면 포함 확인됨 | (종료) |
| `거절` | 크리에이터가 거절함 | (종료) |
| `중단` | 대표 또는 크리에이터가 중단함 | (종료) |

- 상태 전이는 **앞으로만** 진행한다. 뒤로 돌아가지 않는다 (`게시완료`에서 `게시대기`로 복귀 불가).
- 외부 사실(답장 도착·배송 도착·게시 완료)은 **대표가 알려준다** (채팅 또는 CSV 직접 수정).
  에이전트는 대표의 말을 근거로 장부를 갱신하고, 지어내지 않는다.

### `state/outreach.jsonl` (append-only 이벤트 로그)

상태가 바뀔 때마다 한 줄 추가한다:

```json
{"creator_id": "<id>", "handle": "<핸들>", "event": "draft|sent|replied|negotiating|shipped|waiting_post|posted|declined|stopped",
 "at": "<KST ISO>", "note": "<한 줄 메모>"}
```

- `event`는 상태와 1:1로 대응한다 (`draft`=연락대기, `sent`=연락완료, `replied`=답장,
  `negotiating`=협의중, `shipped`=제품발송, `waiting_post`=게시대기, `posted`=게시완료,
  `declined`=거절, `stopped`=중단).
- 이 파일은 Git에 커밋하지 않는다 (SPEC 10.3). 보관 기간 90일.

## 실행 절차

### [1] 활성화 확인 (모든 트리거 공통)

`influencer.enabled`가 `false`(기본값)이면 **no-op 종료**한다.
인플루언서 협업은 대표의 명시적 opt-in 없이는 절대 동작하지 않는다.

### [2] 일일 추적 체크 (main 트리거, 06:40 수집 단계에 편입 — 비치명)

1. `data/influencers.csv`를 읽는다. 파일이 없으면 "협업 명단 없음"으로 기록하고 종료한다.
2. 진행 중인 건(`연락완료`·`답장`·`협의중`·`제품발송`·`게시대기`)마다 기한을 확인한다:
   - `연락완료` 후 `reply_wait_days`(기본 7일) 답장 없음 → **재연락 후보**로 아침 리포트에 기록한다.
     재연락 자체는 하지 않는다. 대표가 결정한다.
   - `제품발송` 후 `post_wait_days`(기본 7일) 게시 없음 → **게시 확인 요청**으로 아침 리포트에 기록한다.
   - `게시대기`에서 `agreed_post_date`가 지남 → **약속일 경과**로 아침 리포트에 기록한다.
3. 기한 초과 건이 있으면 텔레그램으로 알린다 (아침 리포트 발송 시 함께 전달).
4. 기한 초과가 없어도 진행 중 건수를 아침 리포트에 한 줄로 기록한다
   (예: "인플루언서 협업 진행 중 3건 (게시대기 2, 협의중 1)").

### [3] 주간 선정 + 제안 초안 (weekly_calendar 트리거, 일요일 20:00 — 비치명)

캘린더 생성과 같은 트리거에서 수행한다.

1. `data/influencers.csv`에서 `status=선정`인 크리에이터를 읽는다.
2. 목적별 지표로 순위를 매긴다 (인지도→`avg_views` 내림차순, 전환→`save_share_rate` 내림차순).
   지표가 비어 있는 크리에이터는 순위에서 제외하고 "지표 미확인"으로 따로 적는다.
3. 상위 `max_outreach_per_week`(기본 5)건까지 제안 초안을 만든다:
   - 초안 경로: `businesses/<slug>/drafts/YYYY-MM-DD/outreach_<creator_id>.md`
   - 초안 내용: 제안 메일 본문 (브랜드보이스 준수, `knowledge/01_상품서비스.md`·`05_후기_사례.md` 근거),
     크리에이터 정보, 목적, 제안 조건(제품 제공·게시 일정 — 대표는 초안에서 확인하고 정한다).
   - 초안을 만들면 CSV 상태를 `선정` → `연락대기`로 갱신하고, `outreach.jsonl`에 `draft` 이벤트를 추가한다.
4. 답장한 크리에이터(`status=답장`)가 있으면 정성 분석을 한다:
   - 크리에이터의 최근 콘텐츠를 확인하고, 브랜드와의 적합성을 한 줄로 기록한다.
   - 적합하지 않으면 `거절`이 아니라 `중단`으로 기록하고 사유를 적는다
     (크리에이터의 거절이 아니라 우리의 판단이므로 `거절`과 구분한다).
5. 이번 주 선정·초안 결과를 주간 성과 요약(`reports/weekly/`)에 한 단락으로 기록한다
   (analytics 스킬이 합친다 — 이 스킬은 결과를 `logs/`에 남긴다).

### [4] 상태 전이 기록 (대표 보고 시)

대표가 채팅으로 외부 사실을 알리면(예: "A 크리에이터가 답장 왔어", "B 제품 받았대", "C 영상 올라왔어"):

1. CSV에서 해당 크리에이터를 찾는다. 없으면 대표에게 확인을 요청하고 장부를 건드리지 않는다.
2. 상태를 전이표에 따라 한 단계 앞으로 갱신하고, 날짜 필드를 채운다
   (답장→`replied_at`, 발송→`shipped_at`, 게시→`posted_at`+`post_url`).
3. `outreach.jsonl`에 이벤트를 추가한다.
4. 전이표에 없는 점프(예: `선정`에서 바로 `제품발송`)는 하지 않는다.
   중간 단계가 생략된 거면 대표에게 중간 사실을 확인하고 순서대로 기록한다.

### [5] 게시 검수 (게시완료 전)

`게시대기` → `게시완료`로 전이하기 전에 게시물을 확인한다:

1. `post_url`의 게시물을 연다 (공개 게시물).
2. 요청한 장면·표현이 들어있는지 확인한다. 초안에 적힌 요청 사항과 대조한다.
3. 요청 사항이 빠져 있으면 `게시완료`로 전이하지 않고, 아침 리포트에 "게시물 확인 필요"로 기록한다.
   대표가 판단한다.
4. 확인이 끝나면 `게시완료`로 전이하고 `posted_at`·`post_url`을 기록한다.

## 핵심 규칙

1. **기본 비활성.** `enabled=true`는 대표의 명시적 opt-in이다.
2. **제안은 초안까지만.** 이 스킬은 제안 메일·DM을 발송하지 않는다. 발송은 대표가 직접 한다.
3. **외부 사실을 지어내지 않는다.** 답장·배송·게시 여부는 대표가 알려준 것만 기록한다.
   모르면 비워두고 "미확인"으로 표기한다.
4. **상태는 앞으로만 전이한다.** 뒤로 돌아가지 않는다.
5. **목적별 지표로 순위를 매긴다.** 팔로워 수만으로 선정하지 않는다.
6. **정성 분석은 답장한 크리에이터에만 한다.** 답장 전에 정성에 시간을 쓰지 않는다.
7. **주간 신규 연락은 `max_outreach_per_week`를 넘지 않는다** (과도한 연락 방지).
8. **KILL 발동 중에는 트리거 전체를 중단**한다.
9. **장부에 고객 실명·연락처를 기록하지 않는다.** 핸들(공개 계정명)만 기록한다.
10. **API 호출 실패 시 SPEC 8.3 재시도 정책**(최대 3회, 5→15→45분 백오프)을 준용한다.

## 실패 시 처리

| 실패 | 처리 |
|---|---|
| `data/influencers.csv` 없음 | "협업 명단 없음"으로 기록하고 해당 단계만 종료 (비치명) |
| CSV 파싱 실패 | 해당 단계만 실패로 기록하고 다음 단계 진행 (비치명), 리포트에 명시 |
| 대표 보고와 CSV 불일치 (없는 크리에이터) | 장부를 건드리지 않고 대표에게 확인 요청, 리포트에 기록 |
| 전이표에 없는 상태 점프 요청 | 순서대로 기록하도록 대표에게 중간 사실 확인 요청 |
| 게시물 확인 불가 (비공개·삭제) | `게시완료`로 전이하지 않고 "게시물 확인 필요"로 리포트에 기록 |
| KILL 발동 중 | 트리거 전체 중단 + 텔레그램 알림 |
